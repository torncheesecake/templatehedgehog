# Studio v1 positioning

Tagline: Everything before send.

Studio v1 turns the Template Hedgehog archive into a local workflow product. It gives customers a practical place to choose a workflow, edit copy and tokens, compile MJML, inspect preview output, complete QA, prepare a platform handoff, and export a ZIP package.

## What Studio does

- Helps customers choose from the Template Hedgehog workflow archive.
- Lets users edit MJML source directly.
- Provides quick-edit fields for common campaign variables.
- Compiles MJML locally through a Studio-scoped path.
- Updates a desktop or mobile preview after successful compile.
- Tracks grouped QA state.
- Produces a handoff ZIP with source, HTML, QA notes, implementation notes, workflow notes, platform notes, and metadata.
- Makes the platform boundary visible before handoff.

## What Studio does not do

- It does not send emails.
- It does not manage audiences.
- It does not manage GDPR, consent records, or unsubscribe state.
- It does not run automation.
- It does not report campaign analytics.
- It does not connect to Mailchimp, HubSpot, Salesforce, NetSuite, Klaviyo, or Customer.io APIs.
- It does not store customer data in the cloud.

## Why this does not compete directly with Mailchimp

Mailchimp and similar platforms own list management, consent, unsubscribe handling, automation, delivery, and reporting. Studio owns the preparation layer before that work begins. It gives a customer a cleaner source, a reviewed preview, a QA trail, and handoff notes so the sending platform can do its job with fewer mistakes.

## Why Studio makes the archive more valuable

The archive is useful as files. Studio makes it useful as a workflow. Customers can move from a static MJML/HTML package to a repeatable local production process: choose, adapt, compile, QA, and hand off.

## Future integrations

Integrations should wait for customer demand and a stronger security model. A future version could add platform-specific import assistance, token mapping, or validation. It should not add sending, audience management, or consent handling casually, because those features change the product's risk profile.
